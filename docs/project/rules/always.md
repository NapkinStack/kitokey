# Rules of this project — always

> Read with the charter, for every task. These rules add to what every project shares, or
> tighten it; they never repeat it. A rule that concerns one module only belongs in that
> module's `AGENTS.md`.

| # | Rule | Why | Checked by |
|---|---|---|---|
| 1 | Everything written in this repository is in English: documents, code, identifiers, commit messages, pull requests. An input kept as it was given (`docs/project/inputs/`) stays in its own language; so do the sentences the product says to its users, which are its content and are written in each language it speaks — English and French, in the one file a module keeps them in (the decider, 2026-10-13). | Decided by the decider at the discovery's intake, 2026-10-12: the product may become open source, and the framework's forms are in English. | Review. Nobody yet: no check reads a document's language. |
| 2 | A pull request is merged by the agent without waiting for the decider's approval when five things hold: its checks are green — run on the workstation by `nstack attest` and recorded on its head (`checks: attested`; the decider, 2026-10-14 and 2026-10-20: "un user peut faire son dev en interne, GitHub est un opérateur") —, `nstack pr-check` finds it compliant, and a verifier that did not write it has passed its test sheet — or it changes words only —; and in every case, a verifier that did not write it has reviewed its diff. The review is the verifier's, on the forge: what was read, at which head, what was found (the decider, 2026-11-18: « un agent différent de celui qui fait la PR fait une revue avant d'approuver et merger »). **Agents approve each other's pull requests** (the decider, 2026-11-18 evening: « il faut qu'un agent expert puisse approuver les PR des autres, pourquoi pas les uns des autres »), as `.nstack/handbook/07-governance.md` *Where another agent approves* frames it (`approval: agent`). The verifier approves a change to a `standard` module, or to a path `.github/CODEOWNERS` does not name, once its sheet passes — or, where none is owed (words only), once it has reviewed the change on its oracle and its checks — and its review is posted. It approves under its own identity, never the author's nor the last pusher's, and says in the approval the session it ran in and what it is expert in for the module. It approves the head that will merge: after the pull request took the default branch in (G22) and was attested; an update dismisses the approval (G13), so the order is update → attest → sheet and review → approval → merge. It approves in one round: it never pushes to the pull request and never requests changes; a defect goes to the author, and the verifier approves the head that fixes it — or, still in disagreement after that round, hands the pull request to the decider. Everything else still waits for the decider: a `critical` module (`capture`) and the paths `.github/CODEOWNERS` names for a human. This supersedes the « A » of the same day: no agent approved, and G2, G3 and G21 stayed failed. What stays the decider's: a trial on a real call, the state of a deliverable, the forge's settings. | Decided by the decider, 2026-10-13 ("oui, fusionne en autonomie sur summit uniquement"). The forge requires no approval on a private repository of this plan (`discovery.md`, constraints), so the approval was a round trip and not a barrier; the diagnosis says *unguarded* and this rule does not change that. ~~It ends when the repository is opened: the approval can then be required, and is.~~ Kept after the opening ([PDR-0002](../../pdr/0002-the-repository-opened-the-pace-kept.md), 2026-10-25), until the decider reopens it, at the latest on the first contribution from outside the project that the project wants. Once public, the forge refuses what the rulesets set; the approving review is now another agent's, or the decider's where a human must approve (2026-11-18 evening); G2, G3 and G21 are closed by the forge's settings, which are the decider's to set. | The pull request's own checks — `nstack pr-check` requires a complete, passed record of its head (A1, A2) —, and the run that fails when a commit reaches `main` outside a pull request. The forge refuses a merge without its approval once the decider's ruleset requires one; nobody refuses one made short of the other four. |
| 3 | An agent reads a command's output through `rtk` — `rtk-oss` 1.0.1, the Apache-2.0 edition, installed on the workstation, its hook rewriting the agent's shell commands: what passes is collapsed to a count, a failure is kept. When a failure's detail matters — a test that fails, a build that breaks — it is read raw, with `rtk bypass <command>` or from the log the script writes; a long log (the shell's e2e) is written to a file and read with `grep` or `sed`, never whole. | Decided by the decider, 2026-10-18 ("fais les choix pour optimiser les tokens dans summit"), under the framework's line that a command's output is context and that the project names the tool (`.nstack/handbook/04-ai-context.md` §3). `rtk-oss` rather than `rtk`: Apache-2.0 alone, without the compression engine or the proxy that would see the provider's traffic; its telemetry is off until consented to, and stays off. | Nobody: the hook is the workstation's (`rtk init -g --hook-only`); `rtk gain` says what it saved. |
